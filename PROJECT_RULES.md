# PROJECT_RULES.md

## Наследование

Проект следует `GLOBAL_RULES.md`, предоставленному владельцем. Этот файл содержит проектные уточнения.

## Продукт и стадия

- Продукт: личный дашборд Orbit для задач по сферам жизни.
- Пользователь: владелец пространства; в MVP допускаются отдельные изолированные аккаунты.
- Ключевой сценарий: вести задачи между устройствами и переводить задачи направления «ППР» в отдельный рабочий режим подготовки документа.
- Стадия: MVP, зафиксирована 2026-09-01.
- Успех: задачи переживают перезапуск и доступны владельцу на компьютере и телефоне; чужой и анонимный доступ закрыт; узкие агенты создают только проверяемые предложения после явного разрешения владельца.
- Вне этапа: автономный оркестратор, автоматический выпуск полного ППР/ТК, изменение исходных файлов, реальные отправки/бронирования/платежи и совместная работа.

## Стек и архитектура

- Клиент/сервер: Next.js 16, React 19, TypeScript 5.9.
- Облако: Vercel + Supabase Auth/Postgres; локально Next.js с временным хранилищем в памяти.
- Архитектура и ADR: `ARCHITECTURE.md`.
- Бизнес-логика: `lib/tasks.ts` и серверные route handlers.
- Проверки: Oxlint, TypeScript в production build, ручной smoke test.
- Внешние зависимости принимаются только из официального источника с совместимой лицензией и без секретов в клиентском коде.

## Архитектура ИИ-агентов

- Один агент выполняет одну узкую профессиональную роль и не расширяется до универсального помощника.
- Общую маршрутизацию, передачу контекста и совместную работу агентов выполняет отдельный оркестратор.
- Статусы, сроки, сортировка, подсчёты, списки «Сегодня» и «До ситуации» остаются детерминированной бизнес-логикой сервиса; агент их не заменяет и не является источником истины.
- ИИ-диспетчер задач только разбирает задачи, предлагает приоритет и следующий шаг; поиск, календарь, почта и внешние действия относятся к отдельным агентам.
- Разработчик ППР работает только с одним выбранным проектом направления «ППР», а нормативный контроль, AutoCAD и контроль качества передаёт отдельным профессиональным ролям.
- Предложения агентов изменяют данные или запускают внешние действия только после явного подтверждения пользователя.

## Данные и безопасность

- Задачи и история: confidential; могут содержать персональные данные.
- Авторизация: RLS по `owner_id = auth.uid()` и повторная проверка JWT на API.
- Секреты: только переменные окружения; `service_role` в приложении запрещён.
- Резервная копия: экспорт `orbit-tasks-v1`; перед миграцией сохраняется отдельный JSON.
- Откат: убрать переменные Supabase и запустить локально с временным хранилищем в памяти; код и SQL миграции версионируются.
- Российского региона hosted Supabase нет. Реальные данные не переносятся и публичный режим не допускается без отдельного решения владельца по требованиям к размещению и трансграничной передаче.

## Git, готовность и журнал

- Ветка `main`, Conventional Commits, без переписывания истории.
- Готовность: lint и build проходят; авторизация и RLS проверены на владельце, другом и анонимном пользователе; импорт/экспорт и PWA проверены; документация актуальна.
- Журнал: `PROJECT_LOG.md`, обновлять после каждого этапа.
- Команды: `npm install`, `npm run dev`, `npm run lint`, `npm run build`.

## 2026-09-04 — Пакетные публикации и исходники
- Связанные изменения, проверки и документацию объединять в один пакет. Не публиковать промежуточные исправления по отдельности. Хостинг остаётся Vercel.
- Исходники и шаблоны — только для чтения. Не изменять оригиналы и не создавать постоянные копии при анализе. Повторно использовать выбранный источник, распознавая его по содержимому.
- Результаты, исправленные Word-версии и цитаты хранятся отдельно от оригиналов. Старые копии/записи без отдельного согласования не удалять.

По уточнению владельца: после анализа источников подтверждённые свободные поля автоматически заполняются и сохраняются; существующие ручные значения не заменяются молча. Расхождения остаются проверяемыми предложениями, утверждение ТЗ остаётся ручным. Неизвестное не выдумывать, шифр ППР не подменять номером договора, ФИО без должности не предлагать.
