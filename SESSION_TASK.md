# SESSION_TASK.md

## Цель

Подготовить проверяемую версию Orbit с Supabase Auth/Postgres, переносом локальных задач, HTTPS-развёртыванием и установкой на телефон как PWA.

## Исходное состояние

- Ветка: `main`, Git чистый.
- Работает: локальный дашборд и D1, 17 пользовательских задач, экспорт JSON.
- Ограничения: нет входа, удалённого доступа и PWA; API блокирует не-loopback запросы.
- Исходные проверки 2026-09-01: `npm run lint` и `npm run build` успешны.

- [x] Добавить manifest, иконки и service worker без кэширования данных.
- [x] Обновить архитектуру, инструкцию и журнал.

## Что не делать

- Не подключать ИИ-агентов и внешние действия.
- Не помещать реальные задачи, пароли, JWT или `service_role` в репозиторий.
- Не передавать существующие данные во внешний Supabase до решения по юрисдикции.

## Критерии готовности

- [ ] Пользователь входит и видит только свои задачи.
- [ ] Задачи сохраняются после перезапуска и доступны с телефона.
- [x] Backup из 17 задач проходит валидацию и идемпотентно импортирует все записи локально.
- [x] PWA-ресурсы собраны; API не попадает в офлайн-кэш.
- [x] Локальные проверки и документация актуальны.

## Допущения и согласования

- Supabase — временное хранилище MVP по прямому запросу владельца.
- Требует решения: допустимость hosted Supabase для реальных данных или выбор российского размещения; затем нужны URL и publishable key проекта.
