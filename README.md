# Orbit Dashboard

## Рабочее пространство ППР и ТК

В `/work` выбирайте проект из направления «Работа → ППР». Заполните единое ТЗ: документ и объект, обе стороны и подписантов, указания по работам, риски, ТК, графики и рабочие материалы. Можно сначала сохранить неполные вводные и вернуться к ним. Неизвестные риски оставляйте в состоянии «Уточнить».

Руководитель, явно названный в строительном договоре, может быть предложен как подписант по умолчанию с цитатой; полномочия на ППР проверяет владелец. Если должность неизвестна, ФИО и должность не заполняются. В «Проверке предложений» применяйте ФИО вместе с должностью, если она ещё не указана в ТЗ. Изменения не применяются автоматически.

ТЗ сохраняется кнопкой «Сохранить ТЗ», не автоматически. Успешный ответ показывает имя проекта, редакцию и тип хранилища. «Обновить проекты» обновляет неизменённую форму; при собственных правках они сохраняются в форме и конфликт требует решения владельца. «Скачать копию ТЗ» выгружает текущую форму в JSON, включая ещё не сохранённый ввод. При конфликте доступна отдельная кнопка «Скачать мои правки». Автоматического восстановления из JSON пока нет; файл позволяет вручную восстановить значения. Без Supabase локальная база временная и очищается при остановке сервера.

1. Сохраните ТЗ. В облачном режиме оно хранится вместе с задачей в Supabase и доступно в той же учётной записи на других устройствах.
2. Просмотрите открытые вопросы и утвердите редакцию **для разработки**. Это не утверждение ППР к производству работ. Снимок появится в истории, его можно скачать. Изменение вводных потребует повторного утверждения.
3. Для ППР с ТК подготовьте задания по утверждённому перечню. Они связаны с редакцией ТЗ и доступны для скачивания. Автоматический разработчик ТК пока не подключён.
4. Используйте четыре блока под формой: этап разработки, реестр документов, нормативный контроль и ручной чек-лист. Этапы и отметки не означают выполненную агентами проверку.
5. Ниже — шаги, диалог с разработчиком ППР и широкий документ. Для диалога нужен серверный ключ OpenAI и отдельное разрешение на передачу данных. Разработка раздела по локальному шаблону сохраняет прежний выбор фрагментов, синие изменения и версии.

Все будущие агенты остаются видимыми. НТД/качество и исполнитель ТК ещё не подключены. Чтение файлов, предложения SOL, сборка DOCX и подтверждённые правки описаны ниже. Путь к рабочей папке не предоставляет доступ к диску с Vercel. Подробные правила: [PPR_WORKFLOW.md](PPR_WORKFLOW.md).

Личный дашборд задач по сферам жизни. Версия MVP синхронизируется между устройствами через Supabase. В облачном режиме вход обязателен, а строки задач изолированы политиками RLS.

## Папка проекта и ссылка на исходные данные

1. В ТЗ → «Графики и рабочие материалы» укажите **Рабочую папку** (полный локальный путь или путь внутри библиотеки) и, при наличии, **Ссылку на папку с исходными данными**. Нажмите «Сохранить ТЗ». Ссылка синхронизируется с задачей и открывается из рабочего документа. Допускается HTTPS без логина/пароля в URL; не вставляйте API-ключи.
2. В «Рабочий документ» → «1. Исходные данные» выберите папку на компьютере. Браузер покажет файлы, включая вложенные папки. Выбор папки ещё не отправляет её содержимое: отметьте нужные документы, затем нажмите «Прочитать файлы» для предпросмотра текста. SOL получает выбранный текст только после отдельного согласия.
3. Выбор отдельных файлов оставлен для телефона и браузеров без выбора папок. На Vercel диск D: напрямую недоступен. Облачная ссылка пока служит для открытия/скачивания пользователем, автоматический импорт содержимого по URL не подключён.
4. При локальном запуске кнопка «Открыть папку на локальном сервере» читает сохранённую рабочую папку **внутри `ORBIT_LOCAL_FILES_ROOT`**, позволяет переходить по подпапкам и выбирать документы без повторного выбора в системном окне. Переходы за пределы папки проекта и ссылки файловой системы наружу блокируются; оригиналы доступны только для чтения.
5. Сейчас анализируются DOCX, цифровой PDF и UTF-8 TXT: до 2,5 МБ на файл, до 4 файлов / 2,8 МБ на один разбор. Большие PDF, DWG, XLSX и служебные файлы показываются с причиной ограничения. Сканам нужно предварительное OCR. Ограничение выбора папки — 2000 файлов; в видимом списке первые 200 совпадений, остальные найдите поиском. Локальный каталог показывает до 500 элементов одной папки с предупреждением при превышении.

Ссылка и путь сохраняются между устройствами, выбранные файлы — только в текущем окне (копии прочитанных файлов дополнительно остаются в браузере по прежним правилам). Автосинхронизации папок нет. Изменение ссылки не отменяет утверждение содержания ТЗ; изменение рабочего пути сохраняет прежнюю логику повторного утверждения. Решение: [ADR-010](docs/ADR-010-project-source-folders.md).

## SOL, исходные файлы и Word

1. На вызывающем сервере (Vercel или локально) нужен `OPENAI_API_KEY`. Разработчик ППР использует **gpt-5.6-sol**, без подмены другой моделью; `OPENAI_AGENT_MODEL` относится к диспетчеру задач. Подписка Codex не заменяет API-ключ. В карточке агента нажмите «Проверить подключение SOL»: это короткий платный API-вызов без данных проекта.
2. Сохраните хотя бы неполное ТЗ. В «Рабочем документе → Исходные данные» выберите DOCX, XLSX, цифровой PDF или UTF-8 TXT и сначала прочитайте текст. Затем разрешите передачу выбранных файлов (извлечённого текста), ТЗ и подтверждённых примеров в OpenAI. До 8 исходных файлов, 300 000 знаков всего. Для каждого файла укажите назначение. Строительный договор определяет стороны строительства; договор на ППР — поручение разработчику, без автоматической подмены сторон. XLSX показывает листы, адреса ячеек, объединения и предупреждения по сохранённым результатам формул. Изображения и сканы без OCR не анализируются.
3. SOL предлагает значения с проверяемыми цитатами. Отметьте нужные поля; заполненные ранее поля по умолчанию не выбираются. Нажмите «Применить» и утвердите изменённое ТЗ. Файлы появятся в реестре; это не отметка их нормативной проверки.
4. Вкладка «Word-документ»: загрузите собственный DOCX-шаблон, выберите раздел и до 8 фрагментов для SOL. Сохранённый результат привязан к утверждённому ТЗ. Посмотрите текст, укажите два абзаца-заголовка, между которыми нужно заменить текст, подтвердите диапазон и скачайте DOCX. Заголовки, таблицы и остальные части сохраняются; сложные защищённые фрагменты в диапазоне блокируют автоматическую замену. Продолжайте по одному разделу, используя последнюю Word-версию как основу. Неадаптированные части шаблона и титул нужно проверить вручную; это не готовый к производству ППР.
5. «Мои правки»: выберите исходную Word-версию и загрузите исправленный DOCX. Если исходника нет в этом браузере, загрузите его скачанную копию — сервис проверит хеш. Затем выберите текстовые изменения, опишите правило и подтвердите опыт. Только подтверждённые примеры данного проекта используются при последующих запусках; оформление не превращается в правило автоматически. Последние 8 правил и до 3 примеров на правило передаются модели. Это память, не обучение весов SOL.

**Хранение:** двоичные файлы остаются скачанными на устройстве и дополнительно в IndexedDB этого браузера. Vercel обрабатывает выбранный файл временно. ТЗ, цитаты, история версий и подтверждённые примеры хранятся в Supabase в задаче владельца. На другом устройстве файл необходимо выбрать снова. Очистка данных браузера удаляет его копии, поэтому скачивайте важные версии.

**Лимиты MVP:** один файл 2,5 МБ, общий пакет запроса до 2,8 МБ (включая оба DOCX для сравнения); шаблон до 500 000 знаков; разбор исходных данных до 300 000 знаков на пакет (PDF до 100 000 на файл); 20 текстовых версий, 10 разборов ТЗ, 40 Word-версий; сравнение до 2500 абзацев и 40 текстовых изменений по 3000 знаков. Большие объекты разбираются частями. Содержимое не обрезается скрыто. Автоматическое OCR, синхронизация двоичных файлов и автоматический выпуск полного ППР не входят в этот этап.

Проверки: `npm run lint`, `npm run test:ppr`, `npm run build`, `npm run test:ppr-api`. API-тест использует изолированную локальную заглушку модели и синтетические документы, не реальные файлы и не платный OpenAI. Архитектура: [ADR-009](docs/ADR-009-ppr-sol-word.md), [Word/Excel — ADR-011](docs/ADR-011-word-excel-sources.md).

## Локальный запуск

1. Установите Node.js 22.13 или новее.
2. Выполните `npm install`.
3. Запустите `npm run dev -- --hostname 127.0.0.1`.
4. Откройте `http://localhost:3000` (Next.js нормализует loopback-origin в `localhost`).

Без переменных Supabase включается временный локальный режим. Он доступен только с loopback-адреса и не сохраняет задачи после перезапуска.

### Локальная библиотека ППР и ТК

Укажите абсолютный путь в `.env.local`, например:

```dotenv
ORBIT_LOCAL_FILES_ROOT=D:\path\to\your\PPR-library
```

После этого дважды нажмите `START_ORBIT_LOCAL.cmd`. Откроется локальный рабочий экран `http://localhost:3000/work`; сервер слушает только локальный интерфейс. При наличии настроек Supabase задачи синхронизируются с основным сайтом, а библиотека файлов остаётся доступной только через локальный адрес. Закрытие окна локального сервера останавливает доступ к папке.

Локальный экран умеет искать по содержимому распознанных DOCX, PDF и XLSX. Индекс находится в `work/knowledge-index`, исключён из Git и Vercel и не покидает компьютер. После добавления новых шаблонов индекс нужно обновить локальным индексатором; старые DOC сначала потребуется преобразовать в DOCX.

### Агент «Разработчик ППР»

Для запуска агента на сервере задайте секрет `OPENAI_API_KEY`. Не добавляйте его в клиентские переменные `NEXT_PUBLIC_*`. При необходимости модель меняется через `OPENAI_AGENT_MODEL`; по умолчанию используется `gpt-4o-mini`.

В режиме анализа агент рассматривает только выбранный проект ППР и запускается после отдельной галочки в рабочем экране. В модель передаются описание задачи, паспорт проекта и названия записей реестра. Локальная библиотека, бинарные файлы, остальные задачи, email и токены не передаются. Карта разделов рассчитывается самим Orbit и работает без OpenAI; результат анализа остаётся временным.

### Черновик раздела по шаблону

1. Откройте локальный `/work`, войдите в тот же аккаунт и выберите задачу направления «ППР».
2. Заполните паспорт: объект, вид работ, режим с ТК / без ТК. В блоке «Черновик одного раздела» выберите текстовый раздел и распознанный DOCX/PDF из библиотеки, затем сохраните паспорт.
3. Откройте фрагменты и отметьте нужные: до 8 фрагментов, суммарно до 12 000 символов. Поиск и просмотр выполняются локально; таблицы представлены извлечённым текстом, без исходного оформления.
4. Просмотрите выбранный текст и сведения проекта. Только после отдельного разрешения кнопка «Создать черновик раздела» передаст их в OpenAI. Бинарный файл, полный индекс, невыбранные фрагменты и другие задачи не отправляются. Для этого нужен серверный `OPENAI_API_KEY` именно на компьютере, например в `.env.local`; ключ Vercel локальной версии недоступен. После изменения окружения перезапустите сервер. Ключ не следует вводить в чат, задачу или браузерную форму.
5. Проверьте черновик и уточнения. Синий цвет означает новый или изменённый абзац; тёмный — точное совпадение с выбранным фрагментом. Это сравнение текста, а не полная разметка отличий DOCX. Текст можно исправить до сохранения.
6. Отдельной галочкой разрешите сохранить черновик **вместе с выбранными исходными фрагментами** в записи проекта Supabase. Сохраняется новая версия; исходный DOCX/PDF не меняется. Без Supabase локальное хранилище временное — перед закрытием скачайте HTML.

На Vercel и телефоне доступны чтение и скачивание сохранённых версий после входа в тот же аккаунт. Выбор локального шаблона, генерация и подтверждение новой версии пока выполняются на компьютере. Если паспорт, ревизия задачи или файл изменились, сервис потребует актуализировать данные. Нельзя одновременно сохранить два черновика поверх одной ревизии.

Границы MVP: один из шести текстовых разделов, до 20 версий и 500 КБ текста версий на проект; HTML-экспорт с синим цветом, без сборки готового DOCX. Индексирование новых файлов остаётся отдельной локальной операцией. Общий импорт резервной копии пока ограничен 2 МБ: при большом архиве версий дополнительно сохраняйте отдельные HTML. НТД, расчёты, графика AutoCAD и утверждение документа остаются отдельными этапами и ролями. Черновик нельзя использовать для производства работ без инженерной проверки и согласования.

## Подключение Supabase

1. Создайте отдельный проект Supabase. Не используйте ключи другого сервиса.
2. В SQL Editor выполните миграцию `supabase/migrations/202609010001_orbit_tasks.sql`.
3. В Authentication включите Email/Password. Создайте свой аккаунт; после этого для личного сервиса рекомендуется отключить новые регистрации в настройках Supabase.
4. Скопируйте URL проекта и **Publishable key** из Project Settings → API.
5. Создайте локальный `.env.local`:

```dotenv
SUPABASE_URL=https://YOUR_PROJECT.supabase.co
SUPABASE_PUBLISHABLE_KEY=sb_publishable_YOUR_KEY
```

Поддерживается старое имя `SUPABASE_ANON_KEY`. `service_role` приложению не нужен: не добавляйте его в браузер, Vercel или репозиторий.

После входа нажмите **Импорт** и выберите резервную копию `orbit-tasks-v1`. Текущая сохранённая копия находится вне репозитория: `../outputs/orbit-tasks-backup.json`.

## Развёртывание в Vercel и телефон

1. Импортируйте этот репозиторий в Vercel как проект Next.js.
2. В Project Settings → Environment Variables задайте `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY` для Production, Preview и Development. Для ИИ-агентов добавьте `OPENAI_API_KEY` как серверный Secret.
3. Разверните проект. Публикацию нельзя выполнять без настроенной авторизации: локальный fallback намеренно запрещает удалённый API-доступ и не хранит данные после перезапуска.

По HTTPS приложение становится устанавливаемым PWA:

- Android/Chrome: кнопка **Установить на телефон** или меню браузера → «Установить приложение».
- iPhone/Safari: «Поделиться» → «На экран Домой».

Service worker кэширует только иконки. Страницы, API и задачи не сохраняются в офлайн-кэше; без интернета редактирование недоступно.

## Проверки

```text
npm run lint
npx tsc --noEmit --incremental false
npm run test:ppr
npm run build
npm run test:ppr-api
```

Ручной smoke test: вход → список только своих задач → добавление → обновление страницы → экспорт → импорт → открытие с мобильной шириной. Отдельно проверить, что анонимный и второй пользователь не читают и не изменяют строки владельца.

`test:ppr-api` запускает собранный сервер на свободном loopback-порту, отключает Supabase и направляет SDK на локальную имитацию OpenAI. Он использует только синтетические файлы из исключённого из Git `work/test-fixtures`, не расходует API-бюджет и не обращается к рабочей библиотеке. Проверяет согласия, границы доступа, неизменность исходника, выбор данных для модели, правку, две версии, повторное сохранение и устаревшие данные. Тест не заменяет проверку качества ответа реальной модели и RLS двумя аккаунтами.

## Важное ограничение по данным

Hosted Supabase не предлагает российский регион. В задачах могут находиться персональные и рабочие сведения. До переноса реальных данных владелец должен отдельно решить вопрос допустимого размещения и трансграничной передачи либо выбрать российский Postgres/Auth. Техническое решение и путь отката описаны в `ARCHITECTURE.md`.
