# Журнал проекта

## 2026-09-04 — SOL, исходные документы, Word и подтверждённые правки

- Реализованы отдельный PPR-workspace API и интерфейс трёх этапов. DOCX/PDF/TXT читаются с происхождением блоков; SOL предлагает поля с точными цитатами, сервер отбрасывает неподтверждённые значения. Только выбранные предложения меняют ТЗ; прежнее утверждение теряет актуальность.
- Разработчик ППР закреплён за gpt-5.6-sol через существующий Agents SDK, medium reasoning. Диспетчер задач не менялся. Есть отдельная проверка соединения без файлов/сведений объекта. API-ключи не копировались и не выводились.
- Сборка Word сохраняет пакет шаблона, таблицы/колонтитулы/стили/схемы и заменяет выбранную текстовую часть. Сложные диапазоны, макросы, внешние файловые связи и превышение лимитов блокируются. Файлы скачиваются и дополнительно сохраняются в браузере, метаданные и история — в payload задачи. Приём исправленного DOCX проверяет хеш исходной версии; подтверждённые примеры используются только в этом проекте.
- Добавлены fflate 0.8.3, @xmldom/xmldom 0.9.12, unpdf 1.8.1 (MIT); npm audit при установке: 0 уязвимостей. Решение и ограничения: docs/ADR-009-ppr-sol-word.md. Исходные файлы библиотеки и реальные задачи не изменялись.
- Проверки: lint/build, 15 модульных тестов, сквозной API-тест цифрового PDF, SOL-параметров, согласия/цитат, применения ТЗ, Word, истории и памяти пройдены. Модель в тестах заменена локальным HTTP-провайдером; они не подтверждают реальную доступность SOL аккаунта.
- Ограничение проверки: render_docx.py запущен, но LibreOffice/soffice отсутствует в окружении. Файл тестовой сборки создан; визуальная пагинация в Word не подтверждена. Автоматического OCR, исполнителей ТК/НТД/контроля и синхронизации двоичных файлов нет.
- Откат: 29c7557. Схема БД не меняется; новые поля аддитивные. Следующий шаг: проверить опубликованный интерфейс и соединение SOL, затем первый раздел реального проекта после выбора файлов владельцем.
