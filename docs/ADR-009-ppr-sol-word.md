# ППР: SOL, исходные документы и исправления (2026-09-04)

Стадия MVP. Запрос владельца расширяет предыдущую сессию: чтение исходных данных, предложения для ТЗ, сборка Word из шаблона, подтверждённый опыт правок. Роль разработчика ППР остаётся узкой. НТД, исполнитель ТК, AutoCAD и независимый контроль не имитируются.

## Решение

- Сохраняем Next.js, OpenAI Agents SDK и Supabase Auth/RLS. Разработчик ППР использует именно `gpt-5.6-sol`, reasoning medium, без автоматической подмены модели. Диспетчер задач не меняется.
- Сервер проверяет владельца, направление ППР и редакцию задачи перед любым действием. Для обработки файлов используем отдельный API проекта. Предложения ИИ не меняют ТЗ до выбора и подтверждения владельцем. Цитаты сверяются с прочитанными блоками исходного файла. Изменение ТЗ отменяет действительность прежнего утверждения.
- Файлы выбираются пользователем с диска, передаются серверу только для обработки, не сохраняются в файловую систему Vercel. DOCX скачивается на компьютер; дополнительная копия хранится в IndexedDB данного браузера. История версий, хеши, предложения и подтверждённые правки сохраняются в существующем payload задачи. Это НЕ синхронизация двоичных файлов между устройствами: там требуется повторная загрузка. Очистка браузера удаляет его копии, поэтому скачивание обязательно.
- Извлечение цифровых DOCX, PDF и UTF-8 TXT. Скан без текста требует OCR вне текущего этапа. Обработка ограничена объёмом запроса и извлечённого текста; превышение явно блокируется, скрытого усечения нет.
- DOCX собирается детерминированно: сохраняем ZIP-пакет шаблона, стили, колонтитулы, таблицы, нумерацию, изображения и настройки страницы. Выбранные пользователем текстовые диапазоны заменяются проверяемыми версиями разделов. Новые абзацы синие. Сложные фрагменты не удаляются автоматически. Неадаптированные части остаются шаблоном; результат — полный файл-черновик, не утверждённый ППР.
- Исправленный DOCX связан с хешем базовой версии. Правки сравниваются по тексту. Только после отдельного подтверждения выбранные примеры и правило используются как контекст этого проекта. Это память примеров, не обучение весов модели, не основание нормативного соответствия. Оригиналы и предыдущие версии не перезаписываются.

## Библиотеки и альтернативы

- `fflate` 0.8.3 MIT: https://github.com/101arrowz/fflate — ZIP, проверка лимитов до распаковки.
- `@xmldom/xmldom` 0.9.12 MIT: https://github.com/xmldom/xmldom — адресное изменение OOXML, без DTD и внешних сущностей.
- `unpdf` 1.8.1 MIT: https://github.com/unjs/unpdf — извлечение PDF на сервере.
- Python/python-docx подходит для локального инструмента, но требует отдельного runtime на Vercel. Создание DOCX с нуля теряет произвольное оформление готовых шаблонов. Новое облачное файловое хранилище и отдельный локальный сервер пока не нужны.
- Модель: https://developers.openai.com/api/docs/models/gpt-5.6-sol ; миграция: https://developers.openai.com/api/docs/guides/upgrading-to-gpt-5p6-sol . Доступ аккаунта проверяется отдельно от наличия кода/ключа.

## Риски и откат

Лимит файлов обусловлен Vercel; большие проекты разбираются частями. Макросы, встроенные объекты, архивные бомбы и внешние связи DOCX отклоняются. Передача выбранного текста OpenAI только с разрешением в интерфейсе; tracing и store выключены. Нужен серверный API-ключ, подписка Codex не заменяет API-доступ. Откат к `29c7557`; новые поля payload аддитивные, миграций БД нет.
